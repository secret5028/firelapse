# 실행 증거 저장 및 재사용 동등성

2026-10-28. 새 계산 없이 MC 2건을 소급 기록했다.

## 변경

- 서버 MC의 완주 표본 저장 후, 최종 라벨까지 적용한 `playback.json` 옆에 `execution-evidence.json`을 원자적으로 기록한다. 실패 표본에는 기록하지 않는다.
- 입력 스냅샷 SHA, 엔진 소스별 SHA 및 통합 SHA, 계산 옵션, 규칙 설정·manifest SHA, 실제 적용된 문 분류·사용자 정정, 저장 결과 파일 SHA를 포함한다.
- 저장 당시 값은 `started.json`, `input.json`, `sample.json`, 선택된 적분 시도의 `rule_manifest.json`에서 읽는다. 현재 값을 당시 값으로 둔갑시키지 않는다.
- 새 작업은 시작할 때 공통 규칙/조건 코드 SHA도 기록한다. 이전 MC 로그에는 간략 엔진 SHA만 있으므로 소급 건의 공통 코드 SHA는 **소급 검증 시점 지문**으로 별도 표시한다. 당시 규칙은 저장된 manifest와 현재 규칙 컴파일 결과의 일치로 확인한다.
- `saved_case_reuse`는 증거와 실제 파일 해시, 현재 입력 생성 결과, 동일 seed의 표본 입력, 현재 엔진 소스, 공통 코드, 규칙 컴파일 결과를 비교한다. 여기서 표본 생성·규칙 컴파일만 수행하며 적분/CFAST 호출은 없다.
- 증거 누락 또는 어느 항목이든 불일치하면 `historical_result`, “과거 결과 재사용”. 일치하면 `verified_cache`, **“동등 · 검증된 결과 재사용”**. 기존 native 캐시 검증 경로는 유지한다.
- 동등의 의미는 저장된 해당 표본을 현재 입력·소스·규칙으로 재사용할 수 있다는 뜻이다. 실제 화재의 정확성이나 모든 컴퓨터에서의 비트 동일성 보증이 아니다.
