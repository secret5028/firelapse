# C-11 P5 — ROOM 내장재 착화 민감도 결과 (2026-11-03)

400·450·500℃를 각각 순정 CFAST로 1회씩 직렬 실행했다. **400℃만 착화, 기본 450℃와 500℃는 미착화**다. 임계값·연료·개구부·솔버를 결과에 맞춰 변경하지 않았다. P1은 저장 CSV를 다시 분석했으며 엔진 재실행은 없다.

## 4. 입력과 구현 범위

- P1 case.in 원본 전체를 접두부로 보존하고 ROOM 화원 1개·판 타깃 1개와 해당 MATL/CHEM/TABL만 추가했다. 세 덱의 차이는 SETPOINT=400/450/500뿐이다. 공동 화원, 모든 틈·절단 일정·출입문, 15℃ 초기 조건, fan OFF, 출력 5초, MAX_TIME_STEP 1초를 유지했다.
- 연료: 천장 157.5 + 벽 342.7 = 500.2 m², PU 두께 0.1m. 에너지는 지시값 **43,765 MJ**를 그대로 사용했다(면적×0.1×35×25의 산술값 43,767.5 MJ와의 반올림 차이 기록). HRRPUA=400 kW/m², 명목 상한 **200,000 kW**.
- fast는 해당 fire_load_table 클래스 t_alpha=150s를 사용해 α=1000/150²=0.044444 kW/s². 기존 fire_curve의 에너지 70% 후 감쇠·나머지 30% 감쇠 규칙을 유지했다. 따라서 공급 곡선 최고는 **72,123.95 kW**, 전체 적분은 **43,765 MJ**다. 200 MW로 강제 연소시키거나 연료 예산을 늘리지 않았다. 실제 연소는 순정 산소 제한을 받는다.
- 대기 화원 대표 위치 [4.375,9,0]m(ROOM 바닥 중앙). 수평 화원 면적만 ROOM 바닥 157.5m²로 제한한다. 벽·천장 표면에서 퍼지는 불꽃을 공간적으로 계산하는 모델은 아니다.
- 판: [0.3,0.3,5.905]m, 천장 아래 정확히 0.5m, 법선 [-1,0,0], 강판 두께 0.1mm·방사율0.05·k45·ρ7850·c0.46kJ/kgK. 기존 gas_proxy_plate의 모서리·재료·방향 규칙을 재사용했다. 센서 위치를 결과에 맞춰 바꾸지 않았다.
- 순정 TEMPERATURE는 **판 표면 온도가 설정값을 초과할 때** 작동한다. 상층 평균을 직접 입력하는 기능이 아니다. 450℃와 10~15kW/m²의 등가 설명은 사용자 시나리오 가정이며 검증된 PU 재료 착화식/NIST 범용값으로 주장하지 않는다.
- 공동과 새 화원의 CHEM 값은 ID 외 전부 동일(연소열25MJ/kg·복사분율0.35·soot0.1·CO0.05·원소조성 동일). ROOM 예산은 지시대로 공동 예산에 추가했다. 실물 패널 수량과의 중복 여부는 별도 검증되지 않은 입력 가정이다.
- fire_load_table.json 클래스 속성 lining_ignition_C 추가: coldstore_pu_lining=450, 나머지16개 클래스=null. 기존 속성값은 모두 불변이다. null은 기존 규칙 유지이며, 이번 P5 전용 덱 작성기만 새 속성을 소비한다. CLI --threshold 400/450/500으로 고정 민감도를 노출한다.
- 공통 조건표는 기존 코드 그대로 사용. FO 연료 항은 자체 HRR+수신 door jet HRR을 한 번씩 더한다. 산소·온도 항과 다른 3지수 식은 변경하지 않았다.

## 5. 검증 및 산출물

- 엔진 SHA256: `317cd8d1ae914152effe8733fe9fd49e0dc7284acdb041c7d9a57c77eb3467f9`.
- 엔진·공통 조건표·덱 생성기·간략 core·P1 원본 입력 및 CSV 보호 해시 11개 모두 불변. 일반 실행·서버·3D UI 수정 없음.
- 미착화 450℃·500℃는 P1과 공통 구획 CSV **69열 전체 시계열 값이 정확히 동일**하다. 런타임 차이는 실행 측정값이며 물리 결과 차이가 아니다.
- 각 조건 attempt.json 1개, 총 CFAST 실행 3회, 병렬·재시도 없음. 400℃ 덱은 native 래퍼가 추가 행의 LF를 CRLF로 정규화했다. 준비 해시와 실행 해시 차이가 줄바꿈뿐임을 별도 검증했다. 450/500 준비·실행 덱 해시는 동일하다.
- 원시 CSV·덱·센서/연료 명세·실행 로그·보호 해시·지수 원값은 `simulation/results/wando_C11_P5_20261103/`에 보존. `comparison.json`, `index-crossings.csv`는 ROOM과 CAVITY 전부 포함한다.
- 도구: `tools/run_wando_c11_p5.py prepare`, `run --threshold 값`, `report`. 실행 이력이 있으면 재실행/입력 덮어쓰기를 거부한다.

**결론:** 기본 450℃에서는 P1 조건으로 ROOM 내장재 착화가 발생하지 않았다. 400℃ 민감도에서만 자체 연소가 확대되었다. 이 차이를 숨기기 위해 기준·입력을 조정하지 않았으며, 1커밋 후 다음 실행 없이 정지한다.
