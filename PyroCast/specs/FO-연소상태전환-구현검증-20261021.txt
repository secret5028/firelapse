FO 전후 연소 상태 전환 — 구현과 계산 확인
2026-10-21

범위
사용자는 '상변이'를 고체 열분해·기화의 상세 해석이 아니라 FO 전후 연소 상태 전환과 온도·산소·연기 변화라고 확인했다.
이번 지시로 계산 코드 변경과 기능 계산을 수행했다. 앞선 검토 ZIP은 당시 미수정 소스의 스냅샷으로 보존한다.

1. 임계값
criteria.fo_temperature_C=600을 시나리오 내 고정값으로 쓴다. 사용자가 조절할 수 있다.
600℃는 보편 물성 상수가 아니다. NIST FASTLite(1996) 3.3절에는 상층600℃를 FO 전환 기준으로 사용하는 선례가 있다.
현재 CFAST7.7.7에 그 과거 모델의 FO 연료 전환 기능이 그대로 있다는 뜻은 아니다.
온도만 쓰는 criterion='temperature'가 기본이다.
temperature_or_flux를 선택하면 실제 수평 평가면이 있을 때만 바닥 열유속 기준도 쓴다.
유효 평가점이 없으면 바닥 열유속은 null/미평가로 기록한다. 0으로 꾸며 기준 미도달이라고 판단하지 않는다.

2. 계산 흐름
FO 전: 기존 대표 연료별 공급곡선·표적 가열·착화 계산을 유지한다.
FO 조건: 이미 활성 화원이 있는 실에서 설정 온도/유효 열유속의 최초 초과를 찾는다.
저장 시점 사이 교차는 선형 보간하므로 output_step_s에 따른 시각 근사다.
전환은 한 실에 한 번만 적용하는 래치다. 냉각됐다고 연료와 상태를 되돌리지 않는다.

전환 시 잔여 예산:
 E_remaining = sum(E_group - integral(Q_prescribed_group dt before switch))
열분해 공급으로 이미 고체에서 빠진 양을 차감한다. 실제 연소 HRR만 차감해 미연가스를 새 고체로 되돌리지 않는다.
이미 방출된 미연 연료와 기체층/O2/온도는 기존 CFAST 계산 이력 그대로 이어진다.

전환 후 공급 목표:
 Q_target = max(Q_total_at_switch, room_floor_area * configured_HRRPUA)
별도 HRRPUA가 없으면 기존 연료군의 에너지 가중 HRRPUA를 쓴다.
transition_s 동안 선형적으로 총 공급을 확대한다. 예시30초는 프로젝트 탐색값이며 NIST 표준 속도가 아니다.
여러 기존 FIRE가 있으면 기존 공급을 연속적으로 줄이고 대표 FIRE 한 개가 통합 공급을 맡는다.
전환 전 모든 시간/발열량/면적 보간점은 유지한다. 전환 직후 총 공급의 불연속 도약도 만들지 않는다.
등록 FIRE ID는 그대로 유지하지만, 램프 종료 뒤 양의 공급/플룸을 가진 대표 화원은 실당 한 개다.
모든 등록 FIRE의 반복문 자체를 제거하는 엔진 최적화는 이번에 하지 않았다.

램프/유지/감쇠 곡선의 전체 적분은 잔여 예산과 같게 만든다.
잔여 예산이 작으면 램프 시간을 줄인다. 연료 소모 완료 뒤 공급은0이다.
실별 연료를 합칠 때는 유효 연료 화학식과 연소열이 같아야 한다. 다른 연료의 화학을 임의로 같게 만들지 않고 오류로 알린다.
통합 후 개별 그룹 잔량은 전환 시점 잔량 비율로 배분하는 보고용 지분이며 별도 재소비 예산이 아니다.

3. 실제 발열·온도·산소·연기
위 Q_target은 산소가 충분할 때의 처방 공급량이다. 실제 발열량을 강제로 그 값으로 만들지 않는다.
CFAST의 산소/혼합 제한, 종별 생성·소비, 플룸, 두 층 에너지 수지, 벽 열전달을 계속 사용한다.
온도에 임의의 가산값을 넣거나 새 산소를 공급하지 않는다.
벽/기체 복사 및 기존 문 너머 보충 열·직접 화염·문 가스 연소 항은 유지했다.
FO 이후 직접 화염 복사를 무조건 제거하거나 모든 개구부를 같은 화염면으로 취급하지 않는다.
기체 두 층을 갑자기 완전 혼합 한 층으로 바꾸지 않는다.

4. NIST 근거와 프로젝트 확장의 구분
NIST FASTLite SP899(1996): 2.2.9/3.3절, FO 전환과 전환 뒤 연료 조건 지정의 선례.
https://nvlpubs.nist.gov/nistpubs/Legacy/SP/nistspecialpublication899.pdf
CFAST7.7.7 Technical Reference: 3장, 처방 HRR/열분해 공급과 산소 제한. 2장 수지, 5장 열전달.
문서는 복사 피드백에 따른 성장·확산을 자동 예측하지 않으며 사용자가 성장곡선에 반영하는 접근을 설명한다.
https://github.com/firemodels/cfast/blob/CFAST-7.7.7/Manuals/CFAST_Tech_Ref/CFAST_Tech_Ref.tex
CFAST7.7.7 User Guide: FIRE의 시간/표적 온도/열유속 착화와 사용자 지정 화원 입력.
https://github.com/firemodels/cfast/blob/CFAST-7.7.7/Manuals/CFAST_Users_Guide/Input_File_Chapter.tex

따라서 CFAST의 처방 공급·산소 제한·수지 구조에 맞춘 별도 전환 구현이다.
FO 게이트, 면적기반 공급 목표,30초 램프·감쇠분율은 공개된 프로젝트 가정이다.
NIST의 검증된 FO 통합 알고리즘을 그대로 이식했다거나 인증을 받았다는 뜻은 아니다.
실험 대조를 통한 물리 예측 검증은 별도다.

5. 실행 확인
작은 가상1실4x4x3m, 열린 문2x2.1m,3분 계산. 기존 CAD R9와 다른 기능 시험이다.
기준600℃, 전환30초, FO 후500kW/㎡, 배정3000MJ, 가스 확장 반응OFF로 고체 전환 경로를 분리했다.
시험의 얇은 열경계/연료 설정을 실제 건물의 조건으로 적용하지 않는다.
기존 고정곡선 실행과 전환 실행 모두 CFAST 정상 종료. 전환은55.7033초다.
전환 전 상층 온도 차이0℃. 전체 공급곡선 적분3000MJ 보존. 음수 연료/산소 없음.

90초 비교                       고정곡선       FO 전환
실제 HRR                         4.00MW         8.00MW
상층 온도                        724.8℃        1200.0℃
상층 산소 체적분율               11.72%         3.02%
상층 광학밀도                    1.722/m        2.303/m
이 수치는 작동 확인 사례의 계산값이며 건물 예측값/현실 정확도 증거가 아니다.
상층 산소만으로 하층 화원 연소량을 추론하지 않는다. CFAST는 층별 산소와 플룸 유입으로 실제 연소를 제한한다.

기존 R9의30분 결과는 저장값을 다시 평가했다. 모든 계산 실에서600℃ 전환 후보0건이다.
R9 최대471.3789℃. 온도 기준만으로 전환하는 모델이라면 이전 상태에서 변화를 만들 원인이 없으므로 동일 경로다.
기존 입력/결과를 덮어쓰거나 새600℃ 건물 엔진 실행을 했다고 주장하지 않는다.
바닥 열유속20kW/㎡는 여전히 미평가다. 이 별도 기준으로 실제FO 부재를 확정하지 않는다.

6. 위치와 사용
모듈: simulation/pyrocast_cfbt/flashover.py
설정/입력/사건 루프/잔량: model.py, deck.py, spread.py
CAD 설정 전달: cad.py. playback에는 전환 설정과 사건 메타데이터를 전달한다.
독립 입력: simulation/examples/fo_transition_check.json
CAD 연결 설정 예시: simulation/examples/cad_fo600_30min.json (새 전체 건물 계산은 이번에 실행하지 않음)
실행 결과: simulation/results/fo_transition_check/result.json
검사 보고: simulation/results/verification/fo_transition_checks.json

FO 계산은 flashover.enabled=true로 켠다. 기존 설정은 기본OFF로 이전 계산 동작을 보존한다.
외부 사건별 전체 기간 재실행 방식이다. 엔진 내 한 번 실행 최적화는 아직 하지 않았다.
표적·실내 배치·문 너머 직접 복사 대체의 최종 설계는 클로드 검토안과 별도이며 이번에 임의 확정하지 않았다.
기존3D화면의 표시 결과와 예전 클로드 검토 ZIP은 덮어쓰지 않았다.
