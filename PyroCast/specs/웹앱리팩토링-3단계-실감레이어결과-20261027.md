# 3단계 smoke / flame / plume 완료 — 2026-10-27

3단계 메모 2절과 이번 사용자 지시에 따라 기존 실감보기 모듈의 **import 래퍼**만 구현했다. 위험·선택 등 다음 레이어는 진행하지 않고 멈춘다.

## 구현 및 스토어 매핑

- `smoke.js`, `flame.js`, `plume.js`: 독립 레이어 진입점. `real_view_layers.js`로 함께 구성한다.
- `real_view.js`: 단일 legacy 렌더 세션을 공유한다. 세 레이어가 서로 참조하거나 같은 볼륨을 3중 생성하지 않는다. smoke tick에서 프레임당 update/animate를 한 번 호출한다.
- `legacy_real.js`: 원본 CAD와 **원 playback 객체를 그대로** 전달하는 읽기 capability. result 어댑터 출력으로 대체하지 않으며 저장 데이터도 변경하지 않는다.
- 변경 없는 building/resultMeta에서 재생·표시·층·선택 변화는 렌더러와 기하를 재생성하지 않는다. 새 결과 원본이 교체될 때만 기존 자원을 해제하고 다시 만든다.

| update/animate 입력 | 연결 |
|---|---|
| enabled | realView.enabled 및 세 종류 중 하나 이상 ON |
| time | playback.t_s |
| sample | 해당 시각의 원 playback 출력격자 값, 기존 직전값 방식 |
| floor | floor.floor_id, null이면 all |
| smokeEnabled | layers.smoke |
| smokeOpacity | realView.smokeOpacity |
| customRiskBoundaries | true |
| legacySmokeTexture | true |
| flameDisplay | growth |
| plumesEnabled | layers.plume |
| temperatureSmoke | realView.temperatureSmoke |
| animate(ms) | 호스트 clock_s × 1000, reduced motion이면 0 |

기존 스토어에 없던 표시 설정만 `realView` 슬라이스 및 `realView/set`으로 추가했다. 기본 enabled=true, smokeOpacity=1, temperatureSmoke=true는 기존 화면값이다. 계산 설정을 추가한 것이 아니다. 호스트가 `#cfMeaning`을 먼저 제공하며 원본 모듈의 범례 생성 코드는 그대로다. 기존 범례 소유자가 있으면 새 호스트는 충돌을 오류로 알린다.

원본 bridge는 flamesEnabled=true를 고정하므로, 독립 화염 토글 OFF는 update/animate 후 화염 draw object와 해당 조명만 숨긴다. ON 시 다음 원본 update가 상태를 복원한다. 셰이더·화염 크기식·HRR은 수정하지 않는다.

## S09 · 3F · R2 캡처

원본 S09의 fire_key는 CAD_3F_R2_C0이다. **저장 시뮬레이션 시각 1800 s(30분)**를 선택했고, 애니메이션 clock은 별도로 **180000 ms**로 고정했다. Chrome 156 / Three r160 / 1000×700 / 동일 카메라·조명·건물. 기준은 동일 원본 playback을 사용한 createRealView 직접 호출이다.

| 연기 | 플룸 | 보이는 연기 볼륨 | 화염 | 플룸 볼륨 | 다른 픽셀 / 700,000 |
|---|---|---:|---:|---:|---:|
| ON | ON | 19 | 6 | 6 | 0 |
| ON | OFF | 19 | 6 | 0 | 0 |
| OFF | ON | 0 | 6 | 6 | 0 |
| OFF | OFF | 0 | 6 | 0 | 0 |

모든 비교의 최대 채널 차이도 0이다. 연기 ON/OFF·플룸 ON 캡처를 직접 확인했다. 화염 개수는 셀/화원 표시 개수이며 연소한 원래 실 수가 아니다.

연기·화염·플룸의 `uTime`은 활성 개체 모두 180초였다. 화염 맥동의 sizeFlame(now)와 조명 sin(now)도 동일 주입 clock을 받는다. reduced-motion 브라우저 조건에서는 animate 인자와 활성 uTime 모두 0으로 확인했다. clock으로 고정되지 않는 애니메이션 요인은 이번 비교에서 발견되지 않았고, 픽셀 차이를 없애기 위한 uniform 덮어쓰기는 하지 않았다.
