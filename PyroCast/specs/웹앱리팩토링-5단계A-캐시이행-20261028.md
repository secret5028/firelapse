# 5단계 A 보완 1 — 캐시 키 이행 / 저장 결과 재사용

사용자 추가 승인: 검증된 현재 입력·엔진 캐시와 동등성 증명 불가한 과거 결과를 구분한다. 과거 결과에는 “과거 결과 재사용”을 표시하고 재계산하지 않는다.

## 실제 이행 결과
`simulation/results/cache-key-aliases.json`을 1회 생성했다. 옛 키→새 키와 역조회 인덱스 구조를 지원한다. 새 키 직접 조회가 실패하면 검증된 옛 폴더를 찾고, 건물·완료 상태·파일 SHA를 검증한다. 입력·엔진·계산 코드가 달라지거나 파일이 변조되면 반환하지 않는다. 이후 정밀 실행에는 정확한 요청과 완료 파일 SHA를 함께 저장한다.

**현재 옛 24자리 execution_key 항목은 0건이다.** cad_interactive의 16자리 cee3fee4fdeb019a 1건은 다른 키 형식이고, 나머지는 CLI 이름 폴더다. 이전 서버 바이트(fbcab5f)로 키를 재현할 수 없는 항목을 임의로 승격하지 않았다. 따라서 실제 별칭 연결은 0건, 제외 사유1건이다. 빈 별칭 표를 만들어 놓고 캐시 적중했다고 주장하지 않는다.

## 사례 분류
현재 건물 저장 사례42건(native31/lite11)은 모두 현재 입력·엔진·전체 의존성에 대한 정확한 실행 증거가 부족하여 `historical_result`다. 개별 SHA 일부만 일치한다고 새 계산과 동등하다고 보지 않는다. 결과 탭 사례 카드에 라벨·다시 실행 버튼을 추가했다. 버튼은 읽기 전용 재사용 확인이며 솔버를 호출하지 않는다. 이미 열린 같은 사례라면 장면을 다시 만들지도 않는다.

## 확인
- 운영 결과 탭11사례(stage4,S00~S09) 모두 UI에서 다시 실행 클릭. 전부 과거 결과 재사용, 재계산0.
- 42건 분류 API 최대404.82ms. UI 클릭+접근성 관찰까지468~927ms(네트워크 시간만의 수치는 아님).
- 신규 별칭 조회5검사 통과: 1회 이행, 직접 키 우선, 별칭 반환, 입력/건물/파일 불일치 거절, 잘못된 키 형식 제외, 두 라벨 구분.
- 실제 자료의 검증된 캐시 적중0건. 검증된 분기의 동작은 시험 데이터로 검증했다.
- UI에서 새 계산을 실행하지 않으며, 검증 불가한 경우 자동 재계산도 없다.
- 계산 엔진·셰이더 변경 없음. 1항목 1커밋. 다음 항목은 R3·필수2표본 실제 MC 실행이다.
