## 적용

`python tools/build_ui_bundle.py`의 기본 산출물을 실제 서빙 파일 `simulation/viewer/overlay.js`에 생성했다. 소스는 `app/web/entry.js`이며, lite 이외 결과의 기존 경로도 보존한다.

- 실제 `/cfbt/overlay.js` 응답: 176,134 bytes.
- 디스크·HTTP 응답 SHA256 일치: `191014dc90dfdcfe676c79d90e92d1a9f33794ba537d67bf7dde2e4d99908dbe`.
- 초기 캔버스 1개, `#cfMeaning` 1개. 두 화면을 동시에 붙이지 않는다.

회귀 중 발견해 수정한 사항:

1. 새 호스트의 중복 `/cfbt/model-info` 요청을 제거했다. 기존 서버의 lite active/result API가 건물 해시 불일치를 거절하는 것은 소스에서 확인했고 그대로 유지한다. 이후 사례 설치도 최초 payload 해시와 대조한다.
2. 기존 CAD의 ‘선택 층 위 층도 표시’를 새 건물 레이어에 전달했다. 수정 전 상위 층 객체 577개의 가시성이 달랐고 수정 후 0이다.
3. 검토 메뉴의 문 분류·선별·동결 설정 컴포넌트에 선택적인 dispose 반환값을 추가했다. 새 패널이 이를 호출해 타이머, 캔버스 이벤트, 메뉴 3D 객체를 해제한다. CSS link와 레이아웃 상태도 복원하며 `pagehide`에 종료를 연결했다. 메뉴 HTML·문구·계산 기능은 바꾸지 않았다.

- 추적 소유 자원 6,951개, 미해제 0.
- 추가 장면 객체 0, 레이어별 잔여 소유 자원 0.

- 패널·범례·선택 라벨 0, 추가 CSS link 0.

원본 CAD가 소유하는 장면·캔버스는 유지한다(캔버스 1개, 원본 장면 객체 3,744개). 이 수치를 누수로 세지 않는다. 위 검사는 호스트/메뉴의 추적 자원 해제와 구독·타이머·이벤트에 대한 것이며 전체 JavaScript heap의 강제 GC 증명은 아니다.
