남아 있는 수치 정체: 해결했다고 표시하지 않을 것
- 과거 연료 가산 R25 사례는 약 470초에서 DASSL 시간 간격이 극히 작아진다.
  이 과거 덱에는 300초 문 개방 / 450초 창 개방의 수동 일정도 포함되어 있어 최신 고정 초기 개폐 정책과 다르다.
- 닫힌 창 31실 1시간 시험 역시 약 1940초 진행 후 360초 실행 예산에 도달했다.
  종료 상태는 incomplete이며 completed.json / playback.json을 만들지 않았다.
- 따라서 모든 환기 조건에서 1시간이 완료되거나 계산량이 선형 증가한다고 보장할 수 없다.
- 순정 CFAST 개발자도 산소 제한 화재의 수치 정체를 알려진 한계로 설명한다:
  https://github.com/firemodels/cfast/discussions/2118
  이 설명만으로 이번 정체의 단일 소스 결함이 확정되는 것은 아니다.
- 허용오차 완화, 산소 해법 변경, 플룸 호출 교정 등을 격리 시험했으나 해결/동등성 근거가 부족했다.
  특히 산소 해법 시험은 기존 결과가 크게 달라져 채택하지 않았다.
  원본 CFAST·프로젝트 Fortran 확장·운영 실행파일은 r8 상태 그대로 유지했다.
- 이번에 고친 것은 무한 대기처럼 보이는 실행 관리다. 정체/시간 예산 감지 후 해당 자식 프로세스만 종료하고,
  마지막 진행 시각과 미완료 사유를 execution-state.json에 남긴다. 마지막 완료 결과는 유지한다.

창 파괴 구현
- 순정 CFAST 조건형 WALL VENT와 별도 WIN_ 타깃을 사용한다. 창 때문에 외부 재실행을 추가하지 않는다.
- 기본: 일반 비강화 단판 6mm 대용, 전면 판 표면온도 >450℃, 최종 개방률 100% 가정.
  임계값과 최종 개방률은 UI에서 변경 가능. TEMPERATURE/FLUX 선택 가능.
  시나리오 파일에서는 전도율·밀도·비열·두께·방사율 및 창별 정책도 변경 가능.
- 물성: k=.95 W/mK, rho=2500 kg/m3, cp=.82 kJ/kgK, 두께 .006m, 방사율 .90.
- 최종 개방률은 전체 창 면적 기준이다. 초기 .5 → 최종 .8이면 실제 최종값은 .8이다.
- 초기값보다 작아지는 설정·유효하지 않은 물성·수동 중간 개폐와의 혼용은 거부한다.
- 파괴 판정과 1초 개방 전환은 엔진 내부에서 처리한다. > 비교와 비가역 개방을 바꾸지 않았다.
- 실제 개방률은 _vents.csv의 WF_ 열을 VENT ID로 연결해 읽는다.
  후처리와 화면은 직전 관측값을 유지한다. 미래 값 보간으로 창을 미리 열지 않는다.
- 파괴 시각은 '115~120초 개방 변화 관측'처럼 표기하며 정밀한 실제 파괴 시각으로 표시하지 않는다.
- 창 타깃은 연료 타깃 뒤에 별도로 추가하며, 연료 판정은 DEVC ID로 읽는다.
- 외기 창의 타깃은 등면적 CFAST 구획의 정확한 벽 경계에 놓아 순정 외기 뒷면 냉각을 사용한다.
  원본 input.f90/target.f90 확인 결과, '모든 판 타깃은 앞뒤 모두 실내 열을 받는다'는 전제는 해당 배치에 맞지 않는다.
- 현재는 외기 창만 평가한다. 실내 유리의 파괴는 미평가이며 창별로 강제 활성화하면 오류를 낸다.

기본값의 근거와 한계
- Wong, Li & Spearpoint(2014), FSS11 p.449의 Shields 447℃ 언급 및 일반유리 탈락 실험을 참고한 프로젝트 기본값.
  https://publications.iafss.org/publications/fss/11/444/view/fss_11-444.pdf
- 물성 참고: Pagni(2002), Thermal Glass Breakage, FSS7.
  https://publications.iafss.org/publications/fss/7/3/view/fss_7-3.pdf
- NIST가 정한 범용 파괴온도나 검증된 탈락 면적 예측값이 아니다.
- 불투명 판은 유리의 복사 투과, 창틀·음영, 강화·복층, 국부 열응력, 균열 단계를 생략한다.
  실제보다 빠른 가열·개방이 생길 수 있다. 100% 최종 개방은 사용자의 비교 가정이다.
- 타깃은 CAD 실제 창의 상세 열응력을 푸는 표면이 아니라 등면적 CFAST 구획의 개구부 대표점이다.
  CAD 어댑터가 같은 대표 벽에 배치한 여러 창의 실제 국부 온도 차이는 재현하지 못한다.
- 5초 관측은 화면 상태를 늦게 바꿀 수 있다. 외기 유동·온도는 엔진의 내부 개방률로 계산된다.
  고체 추가 착화·FO는 기존 Python 외부 반복이다. '모든 착화 판정이 엔진 내부'라고 표시하지 않는다.

최적화와 구조 정리
- openings.py: 창 정책/타깃/DEVC ID/WF 이력을 한 모듈로 분리했다.
- native.py: 빈 타깃 CSV 처리, WF 로딩, 완료 검증, 정체·시간 예산 및 실패 기록.
- deck.py: 순정 입력만 생성. vendor 및 프로젝트 Fortran 확장을 수정하지 않았다.
- exposure.py/spread.py: 실제 개방률의 공통 조회, WF 인과성 검사, Gauss 적분점 재사용.
- cad.py/practical.py: 선택 층 전체 유지, 남은 연료군과 FO 실 수에 따른 유한 사건 용량.
  고정 6건·8회 제한 대신 자동 용량을 적용하되 전체 시간 예산과 미평가 표시는 유지한다.
  선택 층 100구획 초과는 조용히 잘라내지 않고 명시적으로 거부한다.
- serve_cfbt_building.py: 같은 입력·건물·엔진·코드의 요청은 같은 캐시 폴더를 사용한다.
  원본 출력 해시와 NORMAL EXIT/요청 종료시각 검증을 통과해야 캐시를 재사용한다.
  창 정책도 요청 키에 포함한다. 실제 소형 사례에서 캐시 재사용을 확인했다.
- 큰 JSON 응답은 gzip 전송한다. 31실 30분 재생 약 20.1MB → 약 1.84MB 전송,
  환기된 1시간 재생 약 39.9MB → 약 2.83MB. 계산값/저장 정밀도를 바꾸지 않는다.
- overlay.js: 30분·1시간 선택, 창 설정, 실제 개방률/관측구간, 3D 잔존 유리/청록 개방 테두리,
  창 변화 사건 이동. 회색 전층 연기와 조건별 테두리, FGI 화염 OFF는 유지한다.
- 고체 착화·FO 사건의 일괄 반복은 여전히 전체 시간 구간을 재계산한다.
  엔진 체크포인트/연속 상태 복원은 이번에 도입하지 않았다.
