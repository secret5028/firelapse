검수 의견입니다. 계획의 뼈대는 괜찮고, 빠진 건 대부분 "결과를 나중에 믿을 수 있게 만드는 장부"와 "두 작업이 서로를 오염시키지 않게 하는 격리"입니다.
시작 전에 반드시 할 것 두 가지. 첫째, max항 원복이 정말 원복인지 증명하는 회귀 앵커입니다. 배치 첫 실행은 S09 3F 1시간을 현재 엔진으로 돌려 v8 승인 결과와 해시·연소 실 집합·FO 시각을 대조하는 것이어야 합니다. 이게 안 맞으면 밤새 돌린 25층 결과가 전부 "어느 엔진인지 모르는 결과"가 됩니다. 둘째, 엔진 선택이 사용자 확인 중이면 확인 전에 배치를 시작하지 마십시오. 답이 안 오면 저장 결과들이 쓴 엔진(간략 v8)으로 가되 그 사실을 모든 결과 메타데이터에 적습니다. 건물마다 엔진이 다르면 비교가 무의미해집니다.
시간 예산. 25층 직렬인데 층당 소요가 얼마인지 먼저 재야 합니다(S09 1시간 실행의 실측 시간 기준). 층당 타임아웃을 정하고(예: 20분), 초과하면 상태 timeout으로 기록하고 다음으로 넘어갑니다. 순서는 중요도순으로: 강화 3F(앵커) → 호텔 5F(이미 분석된 층) → 나머지. 09:00에 못 끝낸 층은 미실행이지 0이 아닙니다. BDF가 LOL 전이 근처에서 스텝을 극단적으로 줄여 한 층이 몇 시간을 먹을 수 있으니 타임아웃 없이는 위험합니다.
격리. 앱 버그 검수(Playwright)와 배치 계산이 같은 서버를 쓰면 서로를 오염시킵니다. 검수 중 "실행" 버튼이 눌리면 배치 캐시에 끼어들고, 서버 재시작은 진행 중 계산을 죽입니다. 배치는 CLI 도구(run_lite_*)로 서버 밖에서 돌리고, 검수용 서버는 결과 폴더의 읽기 전용 사본을 보게 하거나 다른 포트로 띄우십시오. 검수 중 서버 재시작 금지.
결과 보존. 시작 전에 기존 결과 폴더 전체의 해시 목록을 뽑아두고(protected-files.json과 같은 방식), 새 결과는 날짜 폴더에만 쓰고, 끝나고 해시 목록이 그대로인지 확인해 보고서에 넣습니다. lite_v8_approved_*와 MC R2 10표본은 어떤 경우에도 덮어쓰지 않습니다.
지름길로 흐르기 쉬운 지점.
1. 호텔 B1 “Opening wider than usable equivalent room CAD_B1_R9”: 개구부 폭을 잘라서 통과시키는 건 금지입니다. 근거 있는 CAD 매핑 수정이 아니면 B1은 blocked로 기록하고 넘어갑니다. 같은 맥락에서 D-3b에 남은 고립 71실·미매핑 127종·로더 실패 4건은 안 고쳐진 상태이니, 호텔 각 층 결과에 "이 층의 고립 실 목록"을 메타데이터로 같이 저장해야 합니다. 화점이 고립 실에 걸리면 전파가 0이 되어 "안전"처럼 보이는데 그건 연결망 결함입니다.
2. 화점 "기존 점수 1위": 그 순위가 어느 선별 실행(run id)·어느 급기 상태에서 나온 건지 기록. 동점 처리 규칙도. 1위 실이 고립 실이면 그대로 쓰되 플래그.
3. 확정 급기: 강화 S00(R3 화점 기준 최악 표본)을 다른 층 화점에 적용하는 건 "그 화점에 대해 최악"이 아닙니다. 쓰는 건 되지만 라벨이 "확정 급기(R3 기준) 적용"이어야 하고, 호텔·견본처럼 확정 없는 건물은 "미확정: 기본 개폐"로 명시. 건물 SHA 가드가 호텔에서 실제로 비활성 처리되는지 한 번 확인.
4. "미평가 0 표시": 가장 위험한 항목입니다. 0은 "안전"으로 읽힙니다. 결과 스키마에서 미평가는 null + 상태 플래그, UI는 “—” 또는 "미평가". 단독 HTML 내보내기와 D-4 AI 어시스턴트 도구 증거 경로까지 null을 제대로 다루는지 봐야 합니다. 어시스턴트가 “FO 0"이라고 근거 인용하면 끝입니다.
5. 완료·실패·시간초과: 상태를 {queued, running, done, failed, timeout, blocked, 미실행}로 고정하고 시각·오류 본문을 남깁니다. 타임아웃 시 부분 재생 데이터를 완료처럼 저장하지 않습니다(저장하려면 status=timeout과 절단 시각 명시). 캐시 키에 엔진 버전·건물 SHA·화점·급기 상태·옵션(radial 등)이 전부 들어가는지 확인. 다른 입력의 옛 캐시가 "완료"로 뜨는 게 "선택 건물·층·실과 결과 불일치"의 전형적 원인입니다.
6. 저장·불러오기: 저장→불러오기→재생 해시·메타 비교 왕복 시험. 건물 A 선택 상태에서 B 결과 불러오기가 거부되는지. 결과 카탈로그가 작업 ID가 아니라 건물 SHA로 키잉되는지(오늘 아침 강화 주소 d018b4bb/90d3c325 불일치가 같은 종류의 버그였습니다).
7. 테스트 분류: 환경 실패(브라우저·포트)는 사유를 적고, 폐기 기대값은 어느 명세가 폐기했는지 인용해 목록만 만듭니다. 밤에 기대값을 고쳐 통과시키지 마십시오. 실패 테스트 삭제 금지.
