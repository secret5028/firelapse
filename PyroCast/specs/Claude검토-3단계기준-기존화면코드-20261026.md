# 3단계 리뷰 기준 — 기존 화면 코드 확인 메모 (2026-10-26)

> 읽은 파일 **[사실]**: `lite_viewer.js`(전체), `legacy_real_view.js`(전체), `legacy_real_bridge.js`(전체), `visualization.py`(전체), `serve_cfbt_building.py`(구조·경로), `overlay.js`(진입부·import). 미독: `risk.js`, `gas_visual.js`, `smoke_visual.js`, `ceiling_jets.js`, `smoke_transport.js`, `lite_doors.js`, `screening.js`, `frozen_rule_controls.js`.

## 1. 계약 초안 정정 (내 추정이 틀린 것)

| 초안 | 실제 코드 [사실] | 조치 |
|---|---|---|
| renderOrder 표: 문 50 < 위험 60 < 선택 70 | 연기 10 · 플룸 15 · 화염 20 · 가스화염 22 · 연기경계 23 · 셀 점선 25 · 띠 26 · 경계면 27/28 · 외부창 30 · **위험 리본 35 · 선택 40 · 실내 문 46** · 코어 70/72/73 | **기존 숫자를 그대로 `render_order.js`에 옮긴다.** 내 표의 순서(문이 위험 아래)는 기준 화면과 다르다 |
| 위험선 z 오프셋 0.015 m × 순서 | 리본 4장(FO·FGI·BD·롤오버 순)을 **연기층 경계 높이**(활성 셀 중 최소 h, 0.16~height−0.5로 clip) + **i × 0.14 m**에 둔다. 리본 폭 0.055/0.04(`joinedSelectionRibbons`) | 기존값 사용. 위험선은 바닥이 아니라 **연기층 높이에 떠 있다** |
| "문이 연기에 가려짐" 원인 = transparent 누락 | 실내 문 선은 이미 `transparent:true, depthTest:false, renderOrder 46` | 내 추정 철회. 이 설정을 그대로 유지하면 된다 |
| 위험 유형 판정 = `conditions.*.met` | 표시 게이트는 `display_v8`에서 온다(아래 3절). `conditions.FGI.met`(공통 조건표, 10 %·LFL)과 **다를 수 있다** | 위험 레이어는 **`display_v8` 호환 게이트**를 쓴다. 조건표 `met`는 상세 패널용. 둘의 불일치는 기록만(동결) |

## 2. 레이어별 이식 기준 (현재 코드 → 레이어)

### building
- `install()` 130~135행: 층 메쉬 색을 `#aab7c0`/`#b8c3cb`, CAD 외곽선 `#bdcbd5` opacity .42로 **덮어쓴다**. 레이어는 이 색 변경을 재현하고, dispose 시 원색 복원.

### openings
- **외부 창**(29~37, 277~311행): `exteriorWindowFace()` 필터(span 0.4~3.01, 높이차 ≤ 2.4, 테라스·난간 제외, 최소 외접 상자, 바깥면 판정). `LineLoop` `#62dcb0` opacity .65 **depthTest true** renderOrder 30. **카메라 방향 판정**(`syncExteriorFacing`, 법선·dot>0)을 OrbitControls `change`에서 수행 → 레이어 `tick`에서 카메라 위치로 매 프레임 판정.
- **실내 문**(40~59행): `kind==='door' && connection_status==='interior'`, leaves(hinge→closed) 또는 폴리곤 최장변, 높이 `door_h||2.1`, z 0.035~height 사각 LineLoop `#e6bd68` .9 depthTest false renderOrder 46.
- 두 그룹은 층 가시성(`groups[i].visible && (all || 해당 층)`)을 따른다.

### core
- 66~83행: `transport` 중 stair/elev, `connected||to_floor||meshes` 없으면 제외. Extrude shell opacity .10 renderOrder 70, 계단 디딤판 .86 r72, 모서리 .95 r73, 모두 depthTest false. **전체 보기 + 체크박스**일 때만.

### smoke / flame / plume
- `legacy_real_view.js` + `legacy_real_bridge.js` **그대로 import**. 셰이더·`createCfastRealistic`·`createCfastPlumeDisplay`·`flameGrowthStyle`·`flameFootprint` 수정 금지.
- 레이어는 `createRealView({THREE,C,groups,B}, data, parentGroup)`를 호출하는 **래퍼**다. 필요한 입력: 카메라 `C`, 층 그룹 `groups`(가시성 판정에 직접 사용), 건물 `B`, playback `data`(원 포맷). → 어댑터 출력이 아니라 **원 playback 포맷**을 그대로 넘기는 것이 가장 안전(셰이더 입력 구조 변경 없음). 스토어는 선택·시간·토글만 준다.
- `update({...})` 인자: enabled, time, sample(index), floor, smokeEnabled, smokeOpacity, customRiskBoundaries:true, legacySmokeTexture:true, flameDisplay:'growth', plumesEnabled, temperatureSmoke. 그대로 매핑.
- `animate(ms)`: `prefers-reduced-motion`이면 0. 호스트 clock의 ms를 넘긴다.
- **DOM 의존 1곳**: 플룸 범례를 `#cfMeaning` 뒤에 삽입(`legacy_real_view.js` 117~119행). 패널이 `#cfMeaning` 요소를 제공해야 한다. 레이어 계약 "DOM 생성 금지" 예외로 기록(셰이더 파일 수정 금지가 우선).

### risk (사용자 정책: 유형별 중첩)
- **데이터 게이트(190~200행, `visualization.states()`와 동일):**
  - FO: `display_v8.color[i] === '#ef4444'`
  - FGI: `smoke_stage[i]===2 && Ou[i] >= LOC_vol_fraction`
  - 백드래프트: `smoke_stage[i]===2 && Ou[i] < LOC_vol_fraction`
  - 롤오버 띠: `rollover_band[i]`
  - 각 유형 독립, 원래 방(`original_room`) 단위로 멤버 셀 OR.
- **기하:** 원래 방 CAD 폴리곤 외곽 리본 4장(색 순서 FO·FGI·BD·롤오버), z = `z_m + min(height−.04, base + i·0.14)`, base = max(.16, min(height−.5, 활성 셀 h 최소)). `MeshBasicMaterial transparent opacity 1 depthTest false` renderOrder 35.
- **셀 점선(v.line, 142·212행):** 셀 경계 ∩ 원래 외곽만, 연기층 높이 h, 색 = `display_v8.color`(없으면 `#9ca3af` 회색 주의), **방이 위험 리본 활성이면 숨김**, `boundary[i]`면 gapSize .25(점선). renderOrder 25.
- **바닥 틴트(v.floor, 141·214행):** 색 있으면 opacity .1, 회색이면 .025, 없으면 0. 이게 유일한 '채움'이다. 유지.
- **연기 경계면(v.interfaceLine/Plane, 145~146·209~211행):** 연기 있고 색 없고 위험 없을 때 점선 `#e7f2fa`, 선택 방이면 반투명 면 .07.
- 상태 문구(206행): "외곽 위험 표시: FO n실 · FGI n실 · 백드래프트 n실 · 롤오버 n실 (현재 층/시점, 저장된 판정)".
- 어댑터는 이 게이트에 필요한 `legacy_color.color`, `rollover_band`, `LOC_vol_fraction`, `smoke_stage`, `O2_upper`, `boundary_by_cell`을 모두 보존하고 있다 **[사실, read.js 확인]**. 따라서 위험 레이어는 어댑터 출력만으로 재현 가능.

### selection
- 141행 바닥 피킹 평면(opacity 0, z+.07, `userData.liteRoom`), 144행 선택 리본 `#42e8ff` .95 depthTest false renderOrder 40, 셀 선택 시 **원래 방 폴리곤**으로 표시(140행).
- 피킹(254~258행): pointerdown/move/up, 드래그 허용 5 px(마우스)/10 px(터치), 멀티포인터면 취소, 보이는 층의 바닥 평면만 raycast. → **호스트가 포인터 이벤트를 소유**하고 selection 레이어에 피킹 평면 목록을 요청.
- 선택 라벨(84·184행) `.cfbtSceneCaption`은 패널 DOM.

## 5. 3단계 합격 판정에 쓸 체크리스트
1. `render_order.js` 숫자가 1절 실제값과 일치.
2. 위험 리본 높이가 연기층 경계 + 0.14 m 간격(바닥 고정 아님).
3. 위험 게이트가 `display_v8` 호환(FO 색·stage2+LOC·rollover_band)이며 `conditions.met`를 쓰지 않음(상세 패널 제외).
4. 셀 점선·바닥 틴트·연기 경계면·선택 리본이 모두 존재.
5. 실감 보기는 `createRealView`를 원 playback 포맷으로 호출, 셰이더 파일 SHA 불변.
6. 외부 창 카메라 방향 판정이 매 프레임 동작.
7. 피킹 드래그 허용치 5/10 px 유지.
8. S06·S09·3F R2 기준 캡처와 clock 고정 비교.
