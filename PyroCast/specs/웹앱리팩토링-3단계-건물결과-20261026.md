# 3단계 첫 레이어 — 건물 완료 (2026-10-26)

최신 `Claude검토-3단계기준-기존화면코드-20261026.md`를 기준으로 진행했다. 건물 레이어만 완료했으며 문·창/코어·연기·화염·위험·선택 레이어는 구현하지 않고 멈춘다.

## 기준 정정 반영

계약 초안의 렌더 순서·바닥 기준 위험선 높이·conditions.met 표시 게이트 추정은 폐기했다. 계약 문서와 `render_order.js`를 실제 기존 코드 값으로 정정했다.

- 연기 10, 플룸 15, 화염 20, 가스화염 22, 경계 23, 셀선 25, 띠 26, 경계면/선 27/28, 외부창 30, 위험 35, 선택 40, 실내 문 46, 코어 70/72/73.
- 위험 리본은 연기층 경계 base + 유형별 .14 m, 기존 상하한 clip 유지. 바닥 고정 오프셋 아님.
- 표시 게이트는 display_v8 호환, 상세 패널은 conditions.met. 이 둘을 합치거나 재계산하지 않는다. 독립 FO/FGI/BD/롤오버 호환 helper 검사 포함.
- 정책 함수는 Group을 거부하고 실제 Mesh/Line과 재질에 적용한다. 위험/문/선택은 transparent 패스. opacity는 최신 검토 문서의 기존값 1/.9/.95로 유지하며, 앞선 일괄 opacity 1 제안보다 최신 문서가 우선한다.

이는 정책·계약 정정이며, 위험선 등 후속 레이어의 실제 표시 구현을 끝냈다는 뜻은 아니다.

## 건물 구현

`app/web/adapters/legacy_building.js`가 기존 CAD 로더의 바닥·벽 밴드·반자·방 바닥·CAD 외곽선을 명시적으로 골라 읽는다. 문짝·유리·코어 투시·라벨 등 후속 레이어 요소는 제외한다. 방/셀 경계로 벽을 새로 만들어 문 구멍이나 테라스 형상을 변경하지 않는다. CAD building.json SHA와 building 계약의 source_hash가 다르면 거부한다.

`app/web/layers/building.js`는 기존 기하를 공유하고 Mesh/Line 개체와 재질만 복제한다. install()의 #aab7c0/#b8c3cb, 외곽선 #bdcbd5·.42를 그대로 적용한다. 원본 재질은 아예 수정하지 않으므로 dispose 후에도 원색이 유지된다. 생성한 재질만 해제하고, 빌린 기하는 CAD 로더가 소유한다. 실화면 전환 때는 legacy 호스트를 먼저 정지하고, CAD 자원 해제 전 새 레이어를 먼저 dispose해야 한다.

building/resultMeta 동일성을 비교한다. 재생·층·선택 변화와 결과 메타만 교체하는 경우 건물 기하/재질을 재생성하지 않는다. 공급 자산이 바뀌었을 때만 개체를 교체한다. 셰이더 새 작성·복사·변경 없음.

Chrome 156, Three.js r160, 동일 렌더러·조명·카메라·1000×700 화면, clock=180000 ms로 비교했다. 기준은 원본 model.html의 실제 CAD 생성 블록과 현재 lite_viewer.js install() 색 변경 블록이다. 그 코드로 만든 **건물만의 기준 장면**과 새 레이어를 비교했다.
