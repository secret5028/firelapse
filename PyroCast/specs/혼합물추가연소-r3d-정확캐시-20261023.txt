혼합물 추가연소 r3d — 동일 입력 복사열 재사용 / 2026-10-23

목적
기존 r3c의 연속 경계와 혼합시간 반응률을 유지하면서, 반복되는 동일 계산을 줄인다.
산소 하한, 착화 조건, FO 기준, 연료량 또는 솔버 허용오차를 완화하지 않는다.

확인한 병목
- 추가연소 OFF / 같은 r2_ventilated/run_01 입력 / O2 빌드도
  600.078초 예산에서 시뮬레이션 3380/3600초까지만 진행했다. 완주가 아니다.
- 이 실행 중 초기 1회와 추가 6회의 호출 스택을 관측했다. 추가 6회 모두
  DASSL의 수치 Jacobian 생성(ddajac) 안이었다. 유동/전도/복사/상태갱신이 함께 나타났다.
- 소수 표본으로 함수별 비용 비율을 추정하지 않는다. 추가연소만 고쳐 모든 비용이
  사라진다고 할 수 없고, 복사열 하나가 유일한 병목이라는 뜻도 아니다.
- O2 OFF 측정 중 디버거 부착/해제 약 1.4초와 별도 시험 빌드 작업이 있었다.
  엄격한 독점 CPU 벤치마크가 아니며 OFF와 ON의 전체 물리 결과는 비교 대상이 다르다.

구현 범위
- vendor/cfast-7.7.7/Source 원본 28개는 그대로다. 별도 확장에 캐시를 구현하고
  생성 빌드 radiation.f90의 RAD4 호출 앞뒤에만 분기한다. 원본 RAD4 수식은 그대로다.
- 따라서 원본 실행파일 그 자체는 아니며, 프로젝트 최적화가 들어간 별도 실행파일이다.
- engine_optimization.radiation_cache 기본 false. 켰을 때만 sidecar에 전달한다.
- 실별 2개 결과 저장. 비교 키는 벽면 온도 4, 가스 온도 2, 방사율 4, 흡수율 2,
  방 크기 3, 층 경계 높이, black 여부와 모든 화원의 복사 발열·x·y·z다.
  실 번호와 키 길이(화원 수)도 구분한다. 원래 전달되는 전체 입력을 포함한다.
- 실수의 비트가 하나라도 달라지면 재계산. 반올림, 허용오차 일치, 시간 지연 재사용 없음.
  NaN/무한대는 재사용하지 않는다. +0/-0도 구분한다.
- 재사용 출력은 벽 복사열 4, 상·하층 흡수열 2, 벽 방출열 4이다.
  RAD4 작업 배열은 호출 뒤 사용되지 않는 것을 원본에서 확인했다.
- 질량·산소·연료·열 source를 추가하지 않는다. 순정 원천항을 그대로 반환한다.
- 별도 case_cfbt_radiation_cache.csv에 exact_hits와 misses만 기록한다.
  카운터는 호출 통계이며 물리적 안전장치 작동 횟수가 아니다.

검증
- 실제 빌드 함수 시험: OFF, 정확 일치 출력, 실 구분, 화원 수 차이,
  모든 키의 최소 1 ULP 변화, 두 슬롯의 기저/교란 재사용, signed zero, NaN 통과.
- Python 90개 검사 통과. 원본/생성 경계 검사 포함; 명시 후크 18개, 생성 변경 파일 6개.
- 소형 compat/smooth/half_step/half_width 모두 r3c O2와 기존 CSV 12종 전체 행이 동일.
  새 캐시 진단 파일만 비교에서 제외했다. 온도 몇 항목만 비교한 것이 아니다.
- 소형 180초 smooth 14.906초. 대응 r3c O2 16.547초이나 1회 측정으로
  일정한 속도 배수를 보장하지 않는다. 작은 사례의 개선은 제한적이다.
- maxdt 절반 누적 추가발열 차이 0.022543%, 상층 온도 최대 차이 0.062609℃.
  캐시 이전과 동일하다. 원래 반응식과 새 반응식 사이의 모델 차이는 r3c 명세 참조.

판정
실제 정체 입력의 1시간 완주, 기존 전체 공통 구간 CSV 일치, 이후 전파 루프 결과를
별도로 확인한다. 성공 전 운영 엔진/3D 데이터를 교체하지 않는다.
16실 목표는 등록 화원 수가 아니라 실제 고체 HRR>1kW인 실로 집계하고,
누적 연소 실 수와 같은 시각 동시 연소 실 수를 따로 보고한다.
