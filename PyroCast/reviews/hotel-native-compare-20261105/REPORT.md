# REPORT HOTEL NATIVE PARTIAL

사용자 선택: 간략 전체 + 호텔 순정 CFAST 대조 1회. 간략 전체 배치는 기존 야간 보고의 25층 중 21층 완료, 1층 수치 실패, 3층 입력 blocked 상태를 유지한다. 이번에 간략 계산을 반복하지 않았다.

## 실행과 비교 범위

- 호텔 5F R16, 야간 저장 input.json을 그대로 사용. r8 manifest 완전 동일, 23구획·19화원·23타깃. 임계값·물리식·엔진 변경 없음.
- 순정 CFAST 1회, baseline 0회, 재시도 0회. 엔진 wall 1800.406 s / 후처리 포함 wrapper 1800.875 s에 예산 종료. 마지막 상태 735/3600 s, **1시간 완주 실패**.
- 보수적 안전 출력 끝 725 s, 간략 저장 격자와 일치하는 **0~720 s만 비교**. 후반 보간·외삽·완료 playback 게시 없음. 운영 화면 결과 자동 교체 없음.
- 같은 간략 사례는 3600 s 완주에 전체 58.062 s, 적분 51.419 s. 서로 완료 구간이 달라 단순 속도 배율을 산출하지 않는다.
- 실제 급기: R16→복도 D16 열림 1, R16 외기 W21/W22 닫힘 0. 전체 개구부 54개 = 닫힘 33·열림 20·fraction 0.01 한 개. 입력 기본 상태이며 MC 최악 조건이 아니다. 창 파괴 OFF.
- native 판 타깃 착화와 lite 상층 기체 온도 착화의 판정량 차이는 남아 있다. 입력 동일이 솔버·모델 동일을 뜻하지 않는다.

지수 계산은 작동한다. 이번 입력에서는 두 엔진 모두 미연 연료 축적을 출력한다. 하지만 300 s에는 실제 HRR이 같아도 온도가 다르고, 600 s에는 실제 HRR부터 크게 다르다. 연소 제한 시점과 층간 열 배분·손실 거동 모두 추가 격리가 필요하며 이번 1회만으로 특정 식을 원인으로 확정하지 않는다. **간략 엔진의 물리 타당성 검증 통과가 아니다.**

R16의 FO·FGI·BD 최고 시각에서 실제 공통식 병목을 추출한 결과 두 엔진 모두 `temperature`이다. 최고 BD 수치가 비슷하다는 사실은 전체 시계열이나 온도가 일치한다는 뜻이 아니다. 상층 산소가 낮다는 사실만으로 미연 연료가 반드시 생긴다고 단정할 수도 없다(300 s의 두 결과 참조). 미연 연료가 적다는 사실은 안전 판정도 아니다.

추가 관찰: 간략 원정밀 상층 O₂에 최저 −0.000078632%의 작은 음수가 있다. 720 s 이내 BD 73표본 중 3개는 이 입력 때문에 공통식이 null로 반환한다. 비교에서 임의로 0으로 바꾸지 않았다. 음수 발생 원인과 보정은 이번 범위 밖이며 수치 미해결로 기록한다.

## 검증·Claude 검토

- native CSV 시간축/실 ID/화원 ID/단위 검증, 고정 개구부 54개 전 시계열 입력과 일치.
- 간략 FGI·BD 23실×2 = 46개 시계열을 원정밀 조건 항으로 재계산하여 저장 공통 조건표와 완전 일치(null 포함).
- source input/manifest/result/playback 4개 SHA 불변. 순정 exe 및 conditions.py SHA 불변. 상세 SHA는 comparison-input-evidence.json.
- native 상층 총질량은 N2/O2/CO2/CO/HCN/HCL/TUHC/H2O/OD 합. 중복 진단 항은 합치지 않음. 1존 구획의 없는 하층 항과 상층질량0 구간은 null 유지.
- 상태 샘플 95개에서 양수 dt 최소 0.0001087 s, 중앙값 0.03005 s. 마지막 상태 steps 38574, dt 0.002714 s. 이는 모든 적분 스텝 통계가 아닌 상태 스냅샷 통계다. 느린 구간과 호텔 10F 수치 실패의 원인이 같다고 추정하지 않는다.
- 종료 후 읽기 전용 프로세스 조회: CFAST/야간 batch/이번 wrapper 실행 중인 프로세스 없음.
- 실제 Claude 데스크톱 기존 야간 중계 대화에 검토만 요청했고, 공통구간 제한·미완료 명시·물리 검증 통과 금지·상층 산소 단독 판단 금지 의견을 받았다. `claude-review.txt`에 보존. 검토 당시 진행 구간 690~730 s 설명은 최종 720 s 공통 비교로 갱신했다. Claude의 예시 ‘병목=연료’는 실제 추출 결과와 달라 채택하지 않았다. 종전 열린 입력은 이번 native 실행 대상이 아니므로 그 입력의 물리 타당성을 입증했다고도 하지 않는다.
