# MC 수치 적분 실패 수정

## 재현과 원인

아이엔테크놀로지 1F R3, 기존 필수 표본 S00의 입력을 그대로 사용했다. 수정 전 BDF는 530.324012초 부근에서 `Factor is exactly singular`로 중단했다. 마지막 저장 표본은 520초이며 실제 실패 시각과 다르다.

Jacobian 162열(1F R16 상층 미연 연료)의 원 상태는 −7.27299768e−12, RHS는 0이었다. 상태/RHS가 유한한데 SciPy `num_jac`의 누적 차분 보정계수가 반복 증가해 무한대가 됐다. 희소 Jacobian의 변화 없는 열에서 차분 크기와 비교하는 RHS 기준이 0이 아닐 수 있어 계수 증가가 누적된다. 실패 상태의 실제 추적은 `trace.json`에 있다. 미분 의존성 누락 검사에서는 누락 열/행이 발견되지 않았다(`sparsity-check.json`).

0열만 계수를 초기화하는 실험은 NaN을 막아도 정체되어 중단했다. 최종 수정은 **각 Jacobian 계산마다 SciPy 초기 계수 sqrt(machine epsilon)에서 새로 시작**한다. 실제 차분은 `sqrt(eps) × max(|상태|, 해당 상태 atol)`에서 시작하며, 현재 평가 내 SciPy 차분 보완은 유지한다. 상태 허용오차는 기존 값 그대로이고 양수/유한 검사를 거친다. 물리 상태·산소·연료값에 임의 양수를 더하지 않는다. NaN/무한대는 정상값으로 바꾸지 않고 오류로 구분한다.

`fresh_jacobian`을 BDF/Radau의 `jac` 콜백으로 전달한다. SciPy 설치본을 수정하거나 전역 monkeypatch하지 않는다. 진단 스크립트의 임시 monkeypatch는 원인 조사/실험용이며 운영 경로에 없다.

## 검증

| 검증 | 전 | 후 |
| --- | --- | --- |
| 기존 S00, 1800초 | BDF/Radau 실패 | BDF 완주, 적분 13.6504초 |
| 기존 S01, 1800초 | BDF/Radau 실패 | BDF 완주, 적분 9.5561초 |
| 사용자 MC10, 각 3600초 | 6표본 연속 실패 후 원인 진단을 위해 나머지 중단 | **10/10 완주, 실패 0, 전체 218.0283초** |

MC10 새 작업: `mc-1793866167503118800-d936ebef`. 이전 작업 `mc-1793862932404583700-e49aa6e0`와 `input.json` 내용이 동일하고, 새 배치 중 엔진 SHA도 불변이다. 표본당 1200초 예산·직렬 실행·개폐 상태·화원·화재 규칙을 유지했다. 10개 playback과 집계가 운영 결과 목록에 등록됐고 S00 선택→1F R3→60분 시간바→30분 결과 표시를 직접 확인했다. 기존 실패 작업/결과는 덮어쓰지 않았다.

기존에 정상 저장됐던 공통 구간 비교: S00(0–520초) 상하층 온도 최대 차이 0.4178K, 산소 질량분율 최대 차이 0.0002315; S01(0–550초) 각각 0.0661K, 0.00000620. 수치 미분 변경 때문에 수치가 완전히 같다고 주장하지 않는다. `partial-state-comparison.json`에 압력/연료 차이도 기록했다. 물리식·조건표·입력 임계값은 변경하지 않았다.

관련 단위 시험 26건 통과: 반복 400회 0열, 강성 선형계 BDF/Radau, 비유한 값 거부, 기존 L1/L1e·누적 상태·door jet. 폐기된 산소 재고 모드 거부 시험의 오래된 오류 문구 기대값만 현재 문구에 맞췄다. 생산 산소 모드 동작 변경 없음.

이 검증은 수치 실패 재현 사례의 회귀 확인이며 전체 물리 타당성이나 모든 건물의 완주 보장이 아니다. 호텔 10F 추가 확인 결과는 별도 JSON에 기록한다.
