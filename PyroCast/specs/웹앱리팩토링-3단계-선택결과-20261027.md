# 3단계 selection 레이어 결과 — 2026-10-27

메모 2절 selection과 사용자 지시 범위만 구현했다. 운영 화면 전환은 아직 하지 않았다.

## 구현

- 선택 리본: #42e8ff, opacity .95, transparent true, depthTest false, depthWrite false, renderOrder 40. 바닥 z+.08. 셀 선택 시에도 원래 방 폴리곤 전체를 사용한다.
- 방만 선택하면 대표 셀 리본 하나만 켠다. 여러 셀의 같은 리본을 겹쳐 그리지 않는다.
- 피킹 평면: 셀 바닥 z+.07, opacity 0, userData.liteRoom=cell_id. 보이는 층과 활성 selection 레이어 평면만 제공한다.
- 호스트가 pointerdown/move/up/cancel·Raycaster를 소유한다. 마우스 5 px, 터치 10 px 이하 허용, 초과·멀티포인터·취소 시 무효. 결과를 selection/set(room_id, cell_id, source)으로 보낸다.
- 빈 공간 클릭은 기존 동작대로 선택을 유지한다. 미선택 상태는 selection/set의 null 값으로 표현한다.
- 레이어는 DOM·이벤트·fetch를 만들지 않는다. .cfbtSceneCaption은 패널 몫으로 남긴다.
- building 동일성이 유지되면 선택·시각·resultMeta 갱신 시 기하를 재생성하지 않는다.

## 캡처 비교

실제 저장 S09·3F·R2 화점, 1800 s, clock 180000 ms. 연기·플룸 ON. Chrome 156 / Three r160 / 1000×700. 기존 lite_viewer.js의 기하 생성 및 update 블록을 수정 없이 기준 장면에서 실행했다.

| 상태 | 선택 대상 | 다른 픽셀 / 700,000 | 최대 채널 차이 |
|---|---|---:|---:|
| R2 선택 | CAD_3F_R2, cell_id=null | 0 | 0 |
| R3 셀 선택 | CAD_3F_R3 | 0 | 0 |
| 미선택 | room_id·cell_id=null | 0 | 0 |

R3는 이 저장 사례에서 분할되지 않은 단일 셀이다. 다중 셀 검증은 R2의 각 셀을 별도로 선택하여 원래 방 기하가 같고 리본이 하나만 켜지는지 확인했다. 미선택 기준 장면은 기존 update에 key=null을 넘겨 모든 선택 비교가 false가 되게 했다. 기존 파일 수정은 없다.

R2·R3 캡처를 직접 확인했다. 이 비교는 건물·실감보기·위험·선택 장면이다. 문·창·코어·패널까지 포함한 S06/S09/R2 전체 화면 전환 검증을 완료했다는 의미는 아니다.

## 동작·해제 검증

- 실제 브라우저 mouse.click과 touchscreen.tap으로 R3 선택 성공, source 각각 click/touch.
- 마우스 5 px 허용·5.01 px 취소, 터치 10 px 허용·10.01 px 취소.
- pointerup에서만 이동한 경우, 멀티터치, pointercancel, 오른쪽 버튼, 다른 포인터 ID 검증 통과.
- 숨긴 층·레이어는 피킹 대상 0, 선택 불가. 선택과 층 변경 후 카메라 불변.
- 38셀의 리본·피킹 기하가 기존 코드와 일치. 500회 갱신 후 buildCount=1, 기하 참조 유지.
- 소유 자원 68개 모두 dispose, 남은 자원·구독 0, 레이어 라벨 DOM 0.
- 호스트 50회 mount/dispose 회귀 검사 통과: 누수 0, 표시 토글 fetch 0, floor/set 카메라 불변.
- 엔진·서버·캐시·기존 뷰어·셰이더 수정 없음. 새 시뮬레이션 0회.
